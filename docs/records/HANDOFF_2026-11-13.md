## 2. 本地启动（Windows / Git Bash 或 PowerShell）

在嵌套仓库根 `F:/111/QAQ/me/AI Agent/Hub/PaintTrack/PaintTrack` 下：

```powershell
$env:LOCAL_DATABASE_ADMIN_URL = "postgres://postgres@127.0.0.1:5433/postgres"  # 需按本机实际填写
$env:PAINTTRACK_LOCAL_MOCK_ROUTING = "1"
$env:PAINTTRACK_LOCAL_WORKER = "1"
node scripts/local-registration.js
```

- 必须用 `node` 直接调脚本：本机 PowerShell 执行策略禁止 `npm.ps1`。
- 启动器只接受 loopback **5433** 上的 `postgres` 管理库，且要求 `CREATEDB`/`CREATEROLE` 或 superuser。
- 默认**复用固定库** `pt_local_auth_000000000000`（账号/会话/任务/资产跨重启保留）；需要干净环境加 `--fresh`。
- **MFA 加密密钥持久化在 `.local-state/mfa-encryption.key`**（gitignore、0600）。复用库时必须保留它：TOTP 密钥是 AES-256-GCM 密文、恢复码是哈希，**删掉或换掉这个文件等于把所有已注册的 MFA 永久锁死**。`--fresh` 走一次性库，配一次性密钥且不写盘。文件损坏会直接报 `LOCAL_MFA_KEY_CORRUPT` 而不是被悄悄重建。
- 默认自动准备 `.local-assets/`（已 gitignore）并同时注入 Web 与 Worker；不要手工给两侧设不同目录。
- 想验证"删除后文件真的消失"，再加 `PAINTTRACK_LOCAL_ASSET_CLEANUP=1`（本地保留期 0 小时、间隔 60 秒）。不设则不常驻清理，`deleted` 记录与文件并存是预期行为。
- 预期输出：`LOCAL_DATABASE_REUSED ...`（或首次 `Retained development database: ...`）、`LOCAL_ASSET_STORAGE_ROOT ...`、`LOCAL_MFA_KEY_PERSISTED .../mfa-encryption.key (existing|created)`（`--fresh` 时为 `LOCAL_MFA_KEY_EPHEMERAL`）、`LOCAL_REGISTRATION_READY http://127.0.0.1:3000/register`（开了清理还会多一行 `LOCAL_ASSET_CLEANUP_ENABLED`）。
- 提交任务后若失败，终端会有一行脱敏诊断 `LOCAL_TASK_FAILURE taskId=... phase=... name=... code=... message=... cause=...`，**这行是排障入口**。

### 清理本地残留（`--prune`）

```powershell
node scripts/local-registration.js --prune            # 只列清单（dry-run，默认）
node scripts/local-registration.js --prune --yes      # 真正删除
```

- 清理对象只有两类：`.next_local_*` 构建目录、`pt_local_auth_*` 历史库及其四角色。`.next/`、`.local-assets/`（用户资产）、`.local-state/`（MFA 密钥）**永不匹配**。
- 默认库 `pt_local_auth_000000000000` 永远保留；owner 不是 `pt_local_migrate_*` 的库、有活动连接的库都会跳过并在输出里说明原因（`PRUNE_DATABASE_KEPT`）。
- 没有 `LOCAL_DATABASE_ADMIN_URL` 时只清构建目录，输出 `PRUNE_DATABASES_SKIPPED`，不会去猜凭据。
- 退出码：0 全部成功（含 dry-run）；1 有条目失败（`PRUNE_DIST_FAILED` / `PRUNE_DATABASE_FAILED`）。
- **已执行过真实清理（2026-11-13，使用者确认后）**：23 个历史本地库全部 `DROP`，回收 196.2 MB，92 个配套角色随之删除，角色总数 57 → 4；固定库 `pt_local_auth_000000000000` 完好（18 张表 / 22 条迁移记录 / users=1、assets=4、generation_tasks=4）。
- **构建目录若被运行中的 dev server 占用就删不掉**：`next dev` + 启动器进程持有 `.next_local_<suffix>`，Windows 下 `unlink` 与 `rename` 都返回 EPERM。此时会输出 `PRUNE_DIST_FAILED` 与 `PRUNE_DIST_HINT`（提示先停服务）并以 exit 1 退出——**预期行为**。本机当前仍有 1 个 `.next_local_93280c294680`（403 MB）就属于这种情况：本地开发环境自 14:24 起一直在跑，停掉后再跑一次 `--prune --yes` 即可清掉。

## 7. 已知坑（都是实际踩过的）

- 仓库根是**嵌套路径**；在父目录执行 `node --check` 会 `MODULE_NOT_FOUND`，重定向日志也会写错位置。
- PowerShell 禁止 `npm.ps1`，用 `node` 直接调脚本。
- 启动器**拒绝**仓库根的 Next 环境文件（`.env*`），不要试图移动/改名绕过。
- `TASK_FAILED` 是接口把非标准错误折叠后的结果，查不到原因；看 `LOCAL_TASK_FAILURE` 行。
- 前端"任务完成但没图"有四种不同原因，别一概而论：①未配置存储根 ②mock 无二进制（已修）③`pool is required`（已修）④真实 Provider 只给 URL（已修，靠 resultFetcher）。
- 本地库每轮随机（历史行为）会导致"每次重启都要重新注册账号"；现在默认复用固定库，`--fresh` 才随机。
- **验收 fixture 会静默落后于代码**：`local-mock-route-postgres` 曾在"没传 `objectStore`"和"用 Worker 身份查未授权列"两处直接失败，`task-executor-postgres` 则仍断言旧的 `kind='mock-asset'`。这些不是业务回归，是上一轮加归档后没同步 fixture。改归档/权限时**务必重跑真实隔离验收**，只跑单测发现不了。
- **Web 角色的 `assets` 写权限是列级的**：只有 `status/updated_at/deleted_at`。用 Web 身份 `UPDATE assets SET mime_type=...` 会 `42501`，不要误判为"删不掉"。表级 `has_table_privilege(...,'UPDATE')` 仍是 `false`，列级 GRANT 不会让它变 true。
