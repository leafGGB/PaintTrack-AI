### 1.2 定下的规则（不得在实现中暗中改值）

- **图片档位**：`size` 字面量**精确匹配**，不吸附最近档、不做比例容差；未登记档位即拒绝创建（`PRICING_RESOLUTION_UNMAPPED`），「源码新增尺寸但价格未跟进」必须走向拒绝，而不是静默降档计费。
- **数量计价三形态**：`per_unit` / `base_plus_increment` / `tiered_total`，必须由价格版本显式声明，代码不得推断；`n` 越上限即拒，不截断、不按上限计费。
- **视频时长**：以**毫秒正整数**为唯一权威单位，区间**左闭右开**；发布期即校验区间不重叠、无空洞、`startMs < endMs`。
- **帧率**：仅枚举匹配，不做最近档吸附；对价格的影响用**纯整数有理数系数**（分子/分母），禁止浮点系数。
- **计时三形态**：`per_second` / `band_total` / `per_frame`，同样由价格版本声明。
- **取整只在最终一步**：单次向上取整到 1 原子单位（0.1 credit），非零最低 1 原子单位；**禁止逐因子取整后相乘**（会系统性高估，与少收同属错误）。
- **溢出**：中间值用整数或 `BigInt`，超上限拒绝创建任务，不截断不回绕。
- **报价是纯函数**：同 `(版本, 规范化输入)` 必须逐位一致，可离线复算对账。
- **对外错误面**：统一 `PRICING_UNAVAILABLE`，响应体不得回显档位、单价、系数、版本内容或内部成本；全部子码一律导致**任务不创建**，不存在「报价失败但照常执行」。

### 7.1 三个关键技术判断

1. **生效判定以时间比较为准，不以状态字段为准。** 报价时直接查「已发布 且 `effectiveFrom <= now()` 且未撤销」的版本，按 `effectiveFrom` 倒序取第一条；被接替的旧版本**不需要**改状态。这样从根上消灭「后台定时任务没跑 → 价格没切」这类静默故障——把后台任务全停掉，报价仍正确切换。`now()` 必须取**数据库时间**：多实例进程时钟漂移会让同一请求在不同实例报出不同价格，事后无法对账。版本表里的 `status` 只作展示与审计，不参与报价判定。
2. **紧急停价必须拆成两种语义**，历史文档混写会直接打错人：
   - `revoke`（停售）：只挡新任务，**在途 quote 照常执行**，常规运营；
   - `invalidate-outstanding`（使在途报价失效）：额外打死未派发 quote，**高风险**，需二次确认 + 独立审计 + 理由，首期建议不开放。
   两者不能绑在同一个按钮上，否则一次「改价停售」会连带打死排队中的正常任务，用户侧只看到「莫名失败」。
3. **报价有效期只约束「派发前」的排队窗口。** dispatch intent 写入后，quote 即固定为结算依据，不再受有效期影响。理由：上游成本已经发生，此时让 quote 过期既不能消成本也不能改价，只会制造「跑完了却不敢结算」的死结。所以 `expiresAt` 的正确用途是限制**排队空等多久还能按老价执行**，不是限制上游跑多久。

### 7.2 资金语义

| 情形 | 已 dispatch | 账务动作 |
|---|---|---|
| quote 过期，未派发 | 否 | 全额 release，任务终态 `price_quote_expired` |
| 紧急失效，未派发 | 否 | 全额 release，`price_quote_invalidated`，须记 actor |
| quote 过期，已派发 | 是 | 不受影响，按原 quote 走 settle/release/unknown |
| `revoke` 后已派发 | 是 | 不受影响 |
| `revoke` 后未派发 | 否 | **仍可派发并按原 quote 结算**（与失效操作的关键区别） |

- **不允许过期后自动按新价重报并继续执行**——那等于用户不知情时改价。将来若要支持，必须是用户显式确认的新请求、新幂等键、新 quote、新 reserve，不能复用原任务。
- 所有释放带 `release_reason`（`quote_expired`/`quote_invalidated`/`system_failure`）与幂等键，便于对账区分自然过期与人为干预。

### 7.3 发布校验与错误面

- 发布即拒三种情况：同一 `modelId` 出现相同 `effectiveFrom`（同秒两版本会让倒序结果不确定）、`effectiveFrom` 早于当前时间（不允许「补一个过去生效」，否则审计上分不清历史依据）、把预约版本插入到已生效版本之前。
- 新增对外粗码：`PRICING_QUOTE_EXPIRED`、`PRICING_MODEL_UNAVAILABLE`（无生效版本或已停售）、`PRICING_QUOTE_INVALIDATED`。三者均表示**未产生扣费**且**不自动重试**（重试会撞上已变的价格，属于变相改价）。
- 与 §4.3.3 的 `PRICING_UNAVAILABLE` 家族并列不合并：前者是「任务压根没建」，后者是「任务曾建但报价不再有效」，用户语义不同。

| 参数 | 推荐 | 取舍 |
|---|---|---|
| 全局默认报价有效期 | **30 分钟** | 太短 → Worker 短暂故障即批量失败；太长 → 改价后仍有大量旧价成交 |

#### 31. HTTP 收费入口：0030 双函数、免费档零冻结与授权时机（2026-11-17）

§30 之后账务链只剩最后一段：**没有任何 HTTP 入口会把报价变成用户实际被扣的钱**。`/api/tasks` 只有默认免费提交（`createTasksHandler`，`routeResolver` 可选、不收费）与本地 mock 路由（`createRoutedTaskHandler`，强制可信快照但仍不收费）。所以本步补收费提交，并同时把「免费档位（`credit_tenths = 0`）」这条路径一次做掉——否则所有零价模型都会被 `CREDIT_FREE_RESERVE_UNSUPPORTED` 挡住。
