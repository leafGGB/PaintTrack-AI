# 阶段 1 小步骤 5：数据治理与运维策略

- 日期：2026-11-04
- 项目：PaintTrack
- 步骤：阶段 1 小步骤 5
- 范围：数据分类、最小化、保留与删除、备份/恢复、监控/告警、秘密管理和运行责任
- 前置基线：阶段 1 小步骤 1–3 报告；阶段 1 小步骤 4 的技术方向已由用户认可
- 决策状态：数据治理总体原则已获用户接受；具体保留期限、法定期限、部署供应商及 RPO/RTO 尚未确认

## 1. 执行摘要

PaintTrack 处理的主要风险数据不只是账户资料，还包括用户媒体、提示词与生成内容、供应商调用引用、额度账本、认证令牌及运维秘密。策略按“服务所需的最少数据、默认私有、服务端授权、分层保留、可验证删除、备份同等保护”执行。

建议采用以下首期基线：

- PostgreSQL 是用户、任务、资产元数据、额度账本和审计记录的业务事实来源；对象存储保存媒体字节，默认私有。
- 本地 Electron 推理不自动上传或进入云端账务；远程 MCP 等第三方路径必须明确告知用户并作为独立数据流处理。
- 认证秘密只存不可逆摘要；供应商/API 密钥只由服务端运行时读取；前端、Electron renderer、数据库业务表和日志均不得保存长期凭据。
- 任务元数据、账本、合规/安全审计与媒体内容采用不同保留规则，不以“任务记录长期保存”推导出永久保存原始素材。
- 备份不替代在线删除：删除流程必须同步安排备份过期或在恢复后重放删除记录。
- 初版建议 RPO ≤ 24 小时、RTO ≤ 24 小时，作为尚待用户确认的规划目标，而非当前系统能力承诺；应在确定地区、托管服务、预算和恢复演练后最终批准。

以下期限均为产品与工程的**建议默认值**，不是法律意见，也不是已配置的生命周期规则。目标服务地区、数据驻留、消费者/未成年人政策、供应商合同、税务/争议处理及法定留存要求确认后，须由负责方复核并调整。

## 2. 治理原则与责任

1. **目的限定与最小化：**每个字段应有明确用途、访问角色和保留期限；无需持久化的原始 prompt、供应商响应或媒体副本不写入数据库/日志。
2. **私有优先：**数据库、对象存储、备份和监控数据均使用最小权限；对象默认私有，下载须执行所有权检查并使用短时授权。
3. **权威来源明确：**PostgreSQL 中的 PaintTrack 身份、任务状态、资产所有权和额度账本是业务权威；客户端缓存、供应商 URL/ID、日志和备份均不是授权依据。
4. **分环境隔离：**开发、测试、预发布和生产的数据库、对象存储、密钥、日志及供应商凭据分开；测试使用合成数据，不复制生产个人数据。
5. **可追溯且最小可见：**记录安全和管理操作的必要元数据；审计读取本身也应受控，避免审计系统成为敏感数据副本。
6. **删除闭环：**账户/资产删除需覆盖数据库、在线对象、缓存和供应商可控副本，并记录待清理状态；备份按到期窗口淘汰，恢复后执行删除补偿。
7. **职责分离：**应用运行身份、迁移身份、备份身份和人工运维身份分开；生产高权限访问需审批、限时和留痕。
8. **供应商边界：**只传完成任务所需的数据；审查供应商保存、训练使用、删除、区域、子处理方和事件通知条款。未确认前不把用户素材用于非任务目的。

## 3. 数据分类与控制

| 分类 | 数据示例 | 默认位置/访问 | 处理要求 |
|---|---|---|---|
| C0 公开/非敏感 | 已批准公开的产品说明、公开模板和帮助内容 | 发布系统；公开内容可读 | 不包含用户数据、秘密或内部运营信息；发布前审查 |
| C1 内部运营 | 部署版本、服务健康、非敏感配置、聚合指标 | 内部运维系统；按职责授权 | 不放凭据；对外导出前检查是否可反推用户或业务秘密 |
| C2 个人与账户数据 | 邮箱、用户 ID、角色、会话元数据、登录/验证状态 | PostgreSQL；认证/授权服务及最小管理员角色 | 仅保留业务必需字段；会话 token 只存 hash；不在普通日志中输出邮箱或 token |
| C3 用户内容与资产 | prompt、工作流定义、上传素材、生成结果、缩略图、文件名、媒体元数据 | PostgreSQL 元数据 + 私有对象存储；所有者/明确授权者可访问 | 默认不公开；上传完成验证；限制大小/类型；避免日志记录原文、对象 key 和可访问 URL；需要时加密传输与静态加密 |
| C4 账务、成本与安全审计 | 额度账本、冻结/结算/释放、人民币供应商成本、管理员操作、滥用/安全事件 | PostgreSQL/受控审计存储；财务/安全职责分权访问 | 追加式或可审计更正；不可静默覆盖；导出严格授权；期限需按争议、税务和适用法规复核 |
| C5 认证与服务秘密 | 密码哈希、验证 token hash、会话 token hash、Provider key、邮件密钥、数据库凭据、签名密钥 | 密码哈希/摘要仅必要字段入库；服务秘密进入部署密钥管理 | 永不写入源码、客户端、普通数据库字段、工单截图或日志；支持轮换、撤销与泄露响应 |
| C6 备份与灾备副本 | 数据库快照/WAL、对象版本/副本、配置备份 | 独立受控备份账户/区域，具体方案待定 | 加密、访问隔离、保留期限和恢复测试；按原数据最高分类保护；删除请求需覆盖到期/恢复流程 |

### 3.1 字段与日志规则

- 默认不记录完整 prompt、上传文件名、媒体内容、完整请求/响应体、邮件验证链接、Cookie、Authorization header、预签名 URL 或供应商错误原文。
- 日志采用 allowlist 字段：时间、环境、服务名/版本、request/correlation ID、内部 task ID、状态/错误分类、耗时、重试次数和必要的数值用量。用户关联优先使用不可直接识别个人的内部 ID。
- 供应商 request reference 仅服务端任务/调用记录需要；向客户端返回 PaintTrack task ID，不将其作为日志标签或 metric label。
- 错误跟踪工具需关闭自动采集请求体、Cookie、环境变量和本地文件路径；发送前脱敏并限制可见人员。
- 计量与监控标签禁止使用邮箱、用户 ID、task ID、asset ID、prompt 或其他高基数/可识别字段。

## 4. 保留、删除与导出策略

以下是建议的首期工程默认值。最终期限取决于目标地区法规、产品承诺和供应商条款；确认前不得将其宣传为已生效的隐私政策。

| 数据类别 | 建议默认保留 | 删除/到期行为 | 注意事项 |
|---|---|---|---|
| 认证邮件 token / 密码重置 token | token 失效后立即不可用；过期记录清理目标 ≤ 7 天 | 清理摘要及投递关联信息；重置/验证事件可保留最小审计字段 | token 使用一次性、短时有效；邮件正文不进入系统日志 |
| 会话 | 活跃会话按产品批准的过期策略；撤销/过期会话记录建议 ≤ 30 天后清理 | 撤销立即生效；清除 token hash | 管理员会话需更短有效期和强化验证策略评估 |
| 任务状态与非内容元数据 | 按已确认基线长期保存，暂定持续到用户删除账户或依法需删除 | 删除账户时去标识化或删除；保留最小账务/安全关联时必须有明确依据 | 不因此永久保留原始输入、供应商响应或输出媒体；“长期”需在对外政策定义期限/含义 |
| prompt、工作流输入快照及供应商请求详情 | 仅完成执行、故障排查与争议处理所需；建议终态后 30 天删除或去标识化 | 按任务/账户删除流程清理；异常延长须有工单、理由和到期日 | 默认不进日志；工作流定义若用户主动保存，按用户资产规则处理 |
| 原始上传素材与生成结果 | 建议默认终态后 90 天；若套餐/用户设置更短则从其规则；失败/孤儿上传建议 7 天内清理 | 用户删除后尽快从在线存储清除；过期对象通过可审计清理任务删除 | 期限须结合成本、套餐、用户控制和供应商能力确认；供应商临时 URL 不作归档 |
| 软删除对象/待清理元数据 | 建议最多 30 天作为恢复/误删窗口；用户明确要求立即删除或法律要求时例外 | 到期硬删除；记录删除任务状态而非保留内容 | 软删除期间不可被用户或普通管理员正常访问 |
| 额度账本、充值/退款、成本与相关管理员操作 | 暂定不少于 7 年的工程规划候选值，**必须由目标地区财务/法律复核** | 到期按适用规则删除或不可逆去标识化 | 不把该建议当作通用法定期限；账本更正应追加冲正记录，不改写原事件 |
| 安全审计事件 | 建议 12 个月在线可查，之后归档/删除；重大事件按调查/法律保全要求单独延长 | 期限届满按策略清除；保全需审批和复核日期 | 仅存事件、主体内部 ID、资源 ID、结果和必要上下文；避免内容正文和秘密 |
| 应用/Worker 运行日志 | 建议 30 天在线；必要时汇总指标保留 13 个月 | 自动轮转/到期删除 | 不记录个人内容或秘密；日志平台供应商和区域待选定 |
| 备份 | 建议数据库日备份保留 35 天、周备份保留 12 周；WAL/PITR 窗口建议 7 天 | 自动过期；账户/资产删除请求在备份过期前以删除台账补偿 | 是否具备该能力取决于托管服务；费用和跨区复制待确认 |

### 4.1 用户删除、导出与法律保全

- 删除请求先验证身份并建立可追踪的删除任务；立即撤销会话和未完成上传/任务访问授权，阻止新的数据处理。
- 删除账户时枚举并处理用户的工作流、任务内容、资产、对象、缩略图及相关缓存；账务/安全记录仅在有经确认的保留依据时保留，并尽量去标识化。
- 删除任务必须具备幂等性、重试、失败告警和完成核验；不能因数据库记录已删就假定对象存储副本也已删除。
- 备份不能可靠逐记录原地擦除时，明确备份到期时间、隔离访问；执行灾难恢复后重放删除清单，未完成补偿前不得开放相关数据访问。
- 数据导出只包含经身份验证用户有权取得的数据，使用短时授权、加密传输和到期清理；禁止把他人数据、秘密或内部安全情报纳入导出。
- 法律保全/争议冻结需由授权责任人审批，记录范围、理由、审批人和复核/解除日期；不允许无期限的无理由保留。

## 5. 备份、恢复与灾难恢复

### 5.1 备份范围与保护

- **PostgreSQL：**托管自动备份与时间点恢复（PITR）为建议基线；保护用户、任务、账本、资产元数据、审计及迁移版本。迁移文件保存在受控版本库，但版本库不是数据库备份。
- **对象存储：**先确认对象版本控制、软删除/误删保护、跨可用区/跨区域复制和恢复成本；不默认开启跨区域复制，须先核实数据驻留与隐私要求。
- **配置与密钥：**应用配置可备份，但秘密优先使用可轮换的密钥管理服务；恢复时重建/轮换凭据，禁止把生产秘密作为普通备份文件长期复制。
- **加密和访问：**备份传输和静态加密；备份访问身份与应用身份分离；恢复操作限于授权运维角色并写审计；加密密钥的备份/恢复与轮换需独立验证。
- **一致性：**数据库资产元数据与对象生命周期/删除台账需可对账；必要时记录迁移版本、备份时间、对象清单摘要和删除水位，避免恢复出不可访问或已删除的资产。

### 5.2 目标与演练

暂定规划目标：

| 目标 | 建议初值 | 状态/定义 |
|---|---:|---|
| RPO（数据库） | ≤ 24 小时 | 最多可接受的数据回退窗口；须依据 PITR/WAL 能力、成本和用户承诺确认 |
| RTO（核心 Web/API） | ≤ 24 小时 | 从确认重大故障到核心服务恢复可用；须包含凭据、数据库和网络依赖恢复 |
| RPO/RTO（对象存储） | 待评估 | 取决于供应商冗余、版本控制/复制能力及素材价值，不能直接沿用数据库目标 |
| 额度账本恢复 | 账本和任务一致性优先 | 恢复后须校验余额可重算、冻结与任务终态一致，必要时进入只读/暂停计费模式 |

- 每季度至少一次恢复演练建议作为上线后目标；首次面向真实用户前应完成一次端到端演练。
- 演练至少覆盖：恢复到隔离环境、应用兼容性、迁移版本、对象读取、删除台账重放、账本重算、健康检查与切回/回滚条件。
- 演练记录恢复点、耗时、缺失数据、费用影响、问题负责人和修复期限；演练不得直接覆盖生产数据。
- 若备份失败、完整性检查失败或 RPO/RTO 无法满足，触发值班告警并限制高风险发布；涉及账务一致性时优先暂停新任务/扣费而非猜测修复。
- 真实恢复、生产数据回滚、破坏性迁移或切换灾备区域均须在执行前获明确批准。

### 5.3 恢复顺序

1. 建立隔离恢复环境并核验访问控制、加密密钥及备份时间点。
2. 恢复 PostgreSQL 到指定时间点，检查 schema/migration 版本和关键表完整性。
3. 恢复或验证对象存储副本；核对资产元数据与对象存在性、大小和状态。
4. 重放备份之后的删除/隐私请求台账，阻止已删除数据重新开放。
5. 对任务、Provider 调用、冻结额度和账本执行幂等对账；不明确任务标记待人工处置，不重复提交供应商任务。
6. 验证认证、API、Worker、私有对象授权、日志告警和关键用户流程后，再按批准的切换方案恢复服务。

## 6. 监控、告警与事件响应

### 6.1 必需观测面

| 面向 | 指标/事件 | 建议告警方向 |
|---|---|---|
| API 可用性 | 请求成功率、5xx、延迟分位数、超时、限流拒绝、request ID | 持续错误率或延迟越过服务目标；阈值在 staging 负载基线后定 |
| Worker/任务 | Worker 心跳、队列积压量/最老任务年龄、租约过期、重试/失败率、终态停滞 | Worker 无心跳、任务年龄持续增长、重试异常上升或任务无法收敛 |
| PostgreSQL | 可用性、连接池使用、事务/锁等待、慢查询、存储空间、备份成功/恢复点年龄 | 连接耗尽、长事务/锁积压、磁盘阈值、备份过期/失败 |
| 对象存储 | 容量/请求/出网、上传失败、完成验证失败、孤儿对象、删除积压 | 成本/容量突增、连续授权/上传失败、删除任务超期 |
| 供应商 | 按 provider/model 聚合成功率、延迟、超时、限流、成本、熔断状态 | 失败率/成本异常、供应商不可用、预算或速率阈值触发 |
| 账务完整性 | 冻结未终结任务、账本与账户余额差异、重复幂等冲突、对账失败 | 任一余额不变量失败立即高优先级告警并暂停相关结算/充值路径 |
| 安全 | 登录失败/限速、权限拒绝异常增长、秘密访问/轮换、管理员敏感操作、删除失败 | 疑似暴力/越权、未授权高权限访问、秘密泄露或删除 SLA 超期 |
| 邮件 | 发送失败、退信/投诉率、抑制列表变化、验证邮件延迟 | 投递质量异常；阈值按供应商基线和账户策略配置 |

- 指标需按环境、服务、错误分类、provider/model 等低基数维度聚合；避免将用户或任务标识写入 metrics label。
- 告警至少定义严重级别、值班责任人、响应时限、升级路径、操作手册链接和解除条件；生产发布前指定实际负责人。
- 数据面板采用最小字段；对访问、导出和配置变更留痕。告警通知渠道和 on-call 平台待选型。

### 6.2 事件分级与初步处置

- **SEV-1：**疑似密钥泄露、跨用户数据暴露、账本不变量损坏、生产数据丢失/加密攻击、持续不可用。立即限制影响面、撤销/轮换凭据、暂停相关任务/扣费或下载、保护证据并通知责任人。
- **SEV-2：**显著任务积压、供应商/邮件大面积故障、备份恢复能力失效、删除请求大量失败。启动故障手册、切换/限流或暂停相关功能，持续跟踪恢复目标。
- **SEV-3：**局部可降级故障、单任务异常或非关键指标偏离。创建事件记录与修复期限，按日常值班处理。
- 所有级别均记录发现时间、影响范围、数据类别、处置动作、决策人、是否涉及个人数据、恢复验证和后续改进；不得在事件工单粘贴完整秘密或用户素材。
- 是否须对用户、监管方或供应商通知及通知时限由目标地区法律与合同决定；上线前指定责任人和法律审查路径。

## 7. 秘密管理

### 7.1 存放与访问

- 生产秘密存入托管部署平台的 Secret Manager/KMS 或等价受控机制；本地开发使用未跟踪的本地环境变量/密钥存储，仓库只提供不含真实值的变量名与示例。
- 秘密按环境、用途和服务身份分开：数据库应用连接、迁移连接、备份身份、对象签名身份、Provider key、邮件密钥、会话/CSRF 签名材料分别管理。
- Web/API 与 Worker 只获得自身所需秘密；迁移凭据不注入常驻 Web/API；Electron renderer 和浏览器不得取得服务端秘密。
- 生产秘密访问采用最小权限、个人身份、审批/短时授权和审计；禁止共享个人管理员账号；开发者默认无生产读取权。
- 不通过 URL query、命令行参数、构建参数、前端公开变量、崩溃转储或日志传递秘密；部署工具须确认不会打印环境值。

### 7.2 生命周期与响应

- 新建秘密时指定负责人、用途、环境、权限、创建日期和轮换/过期策略；密钥轮换支持新旧短暂并存、验证切换、撤销旧值及回滚预案。
- 轮换节奏按供应商能力、风险等级与适用政策确定；高权限凭据、签名密钥和 Provider key 泄露时立即撤销/轮换，不等待计划周期。
- 邮件验证/重置 token 与会话标识使用高熵随机值；服务端存 hash，短时有效、一次性消费，支持撤销和限速。
- 密码仅使用经维护的标准密码哈希算法/库及合适参数；不得自行设计加密算法，参数在认证实现步骤单独评审。
- 定期执行仓库秘密扫描、部署配置审查和权限复核；发现真实秘密进入 Git 时，不能只删除文件或改写提交，必须先按已暴露处理并轮换，然后评估历史记录与副本。
- 备份/恢复和灾难演练须验证加密密钥可用性，但禁止将主密钥与密文备份放在相同访问边界。

## 8. 运行治理与操作手册要求

上线前至少建立以下受控运行手册：

- 数据访问、用户导出/删除、删除失败重试和法律保全审批；
- 数据库备份状态、恢复演练、迁移失败停止/回滚与账务对账；
- Worker 积压、租约过期、供应商故障、任务人工处置和幂等重试；
- 对象存储误删、泄露的短时链接撤销、孤儿对象清理和成本异常；
- 秘密新增、轮换、撤销、泄露响应和环境访问审批；
- 事件分级、值班联系、证据保全、通知决策与复盘。

人工运营操作应采用可审计管理身份、二次确认和最小权限。对充值、账本调整、批量导出、删除豁免、任务重新提交、密钥轮换和生产恢复等高影响动作记录操作者、审批者、目标、前后状态、原因及关联事件；账务调整只追加冲正/调整事件，不直接改写既有账本事实。
